Computer-controlled characters need two things: a way to get around
the level without walking into walls (**pathfinding**), and a way to
decide what to do (**behaviour**). `examples/ai.nb` shows both.

## Navigation meshes

A **navigation mesh** (navmesh) is a map of the ground characters can
walk on. Make one from your level once, after loading it:

```basic
level = LoadMesh("levels/castle.glb")
EntityPickMode level, 2                      ; navmeshes are made from pickable geometry
nav = GenerateNavMesh(-50, -50, 100, 100)    ; look down over this area
```

| Command | Makes a navmesh |
|---|---|
| `GenerateNavMesh(x, z, width, depth [, cell_size, ...])` | by looking down on the pickable entities over an area: works with any level |
| `CreateNavMesh(entity [, max_slope])` | from one mesh's triangles, keeping slopes that are not too steep |

`NavMeshEntity(nav)` makes a visible copy, to check what is walkable:

```basic
nav = GenerateNavMesh(-50, -50, 100, 100)
debug = NavMeshEntity(nav)
EntityColor debug, 0, 255, 0
EntityAlpha debug, 0.4
```

## Agents: characters that walk by themselves

An **agent** walks over a navmesh on its own: you say where to go, and it
finds the way round walls, turns to face where it is going, and keeps out
of other agents' way.

```basic
nav = GenerateNavMesh(-50, -50, 100, 100)
guard = LoadAnimMesh("examples/media/CesiumMan.glb")
walker = CreateAgent(guard, nav, 3)          ; walks at 3 units a second
AgentMoveTo walker, 20, 0, 35                ; go there
; each frame:
If AgentArrived(walker) Then AgentMoveTo walker, Rnd(-40, 40), 0, Rnd(-40, 40)
```

| Command | Does |
|---|---|
| `CreateAgent(entity, nav, speed [, radius])` | makes the entity an agent |
| `AgentMoveTo agent, x, y, z` | walks to a point |
| `AgentFollow agent, entity, distance` | keeps following an entity, stopping within `distance` |
| `AgentStop agent` | stops |
| `AgentArrived(agent)` | 1 when it has got there |
| `AgentDistance(agent)` | how far it still has to go |
| `AgentSpeed`, `AgentTurnSpeed`, `AgentRadius` | how fast it walks and turns, and its personal space |

Agents move during `UpdateWorld`.

## Paths

To plan a route without an agent (to draw it, or to check a place can be
reached), ask for a **path**:

```basic
nav = GenerateNavMesh(-50, -50, 100, 100)
path = FindPath(nav, 0, 0, 0, 30, 0, 40)
If path = 0
    Print "can't get there"
Else
    Print "route of " + PathPoints(path) + " points, " + PathLength(path) + " units long"
    For i = 0 To PathPoints(path) - 1
        Print PathX(path, i) + ", " + PathZ(path, i)
    Next
    FreePath path
EndIf
```

## Grid paths for 2D and strategy games

For games played on a grid (a 2D dungeon, a strategy map), a **path
grid** finds the cheapest route between cells. Each cell has a cost:
1 is normal, higher is slower to cross (mud, forest), 0 is blocked.

```basic
grid = CreatePathGrid(10, 10)
For y = 0 To 7
    SetPathCost grid, 5, y, 0              ; a wall with a gap at the bottom
Next
SetPathCost grid, 2, 2, 4                  ; a swamp: crossable, but slow
path = FindGridPath(grid, 0, 0, 9, 0)
For i = 0 To PathPoints(path) - 1
    Print PathX(path, i) + ", " + PathY(path, i)   ; column, row
Next
```

`TileMapPathGrid(map)` makes a grid from a [tile map](14-2d-games.md#tile-maps),
with every tile blocked and every empty cell open.

## Behaviour trees

A **behaviour tree** decides what a character does, from simple rules
written as a tree: "if the player is close, chase; otherwise, if hurt,
run away; otherwise patrol".

Write the tree in a text file, one node per line, children indented
under their parent:

```text
selector
  sequence
    if health < 30
    do flee
  sequence
    if distance < 10
    do chase
  do patrol
```

| Node | Means |
|---|---|
| `selector` | try each child in turn until one succeeds |
| `sequence` | do each child in turn while they succeed |
| `invert` | its child's success counts as failure, and the other way round |
| `if condition` | succeeds when the condition is true; compares parameters and numbers |
| `do action` | an action for the program to carry out |

The program gives each character's parameters, asks the tree which
action to do, and does it:

```basic
guardMesh = CreateCube()
player = CreateSphere()
brain = LoadBehavior("guard.txt")
SetBehavior guardMesh, brain
; each frame:
SetBehaviorParam guardMesh, "distance", EntityDistance(guardMesh, player)
SetBehaviorParam guardMesh, "health", 80
Select BehaviorAction(guardMesh)
    Case "chase" : PointEntity guardMesh, player : MoveEntity guardMesh, 0, 0, 0.1
    Case "flee" : PointEntity guardMesh, player : MoveEntity guardMesh, 0, 0, -0.1
    Case "patrol" : TurnEntity guardMesh, 0, 1, 0
End Select
```

The tree is checked every time `BehaviorAction` is called, so a more
important branch takes over as soon as its condition becomes true (the
guard stops patrolling the moment the player comes close). When an
action has finished, `BehaviorResult entity` tells the tree, so a
`sequence` can go on to its next step.

Trees can also be built in code (`CreateBehavior`, `BehaviorSelector`,
`BehaviorSequence`, `BehaviorIf`, `BehaviorDo`) or from a string with
`BehaviorFromText`. One tree can be shared by every guard: each
character keeps its own parameters and progress.
