# 20. AI and pathfinding

[Contents](../MANUAL.md) · Previous: [19. Collisions and physics](19-collisions-physics.md) · Next: [21. Building worlds](21-worlds.md)

Computer-controlled characters need two things: a way to get around
the level without walking into walls (**pathfinding**), and a way to
decide what to do (**behaviour**). `examples/ai.nb` shows both.

## Navigation meshes

A **navigation mesh** (navmesh) is a map of the ground characters can
walk on. Make one from your level once, after loading it:

```basic
level = LoadMesh("levels/castle.glb")
EntityPickMode level, 2                      ; navmeshes are made from pickable geometry
nav = GenerateNavMesh(-50, -50, 100, 100)    ; look down over this area
```

| Command | Makes a navmesh |
|---|---|
| `GenerateNavMesh(x, z, width, depth [, cell_size, ...])` | by looking down on the pickable entities over an area: works with any level |
| `CreateNavMesh(entity [, max_slope])` | from one mesh's triangles, keeping slopes that are not too steep |

`NavMeshEntity(nav)` makes a visible copy, to check what is walkable:

```basic
nav = GenerateNavMesh(-50, -50, 100, 100)
debug = NavMeshEntity(nav)
EntityColor debug, 0, 255, 0
EntityAlpha debug, 0.4
```

## Agents: characters that walk by themselves

An **agent** walks over a navmesh on its own: you say where to go, and it
finds the way round walls, turns to face where it is going, and keeps out
of other agents' way.

```basic
nav = GenerateNavMesh(-50, -50, 100, 100)
guard = LoadAnimMesh("examples/media/CesiumMan.glb")
walker = CreateAgent(guard, nav, 3)          ; walks at 3 units a second
AgentMoveTo walker, 20, 0, 35                ; go there
; each frame:
If AgentArrived(walker) Then AgentMoveTo walker, Rnd(-40, 40), 0, Rnd(-40, 40)
```

| Command | Does |
|---|---|
| `CreateAgent(entity, nav, speed [, radius])` | makes the entity an agent |
| `AgentMoveTo agent, x, y, z` | walks to a point |
| `AgentFollow agent, entity, distance` | keeps following an entity, stopping within `distance` |
| `AgentStop agent` | stops |
| `AgentArrived(agent)` | 1 when it has got there |
| `AgentDistance(agent)` | how far it still has to go |
| `AgentSpeed`, `AgentTurnSpeed`, `AgentRadius` | how fast it walks and turns, and its personal space |

Agents move during `UpdateWorld`.

## Paths

To plan a route without an agent (to draw it, or to check a place can be
reached), ask for a **path**:

```basic
nav = GenerateNavMesh(-50, -50, 100, 100)
path = FindPath(nav, 0, 0, 0, 30, 0, 40)
If path = 0
    Print "can't get there"
Else
    Print "route of " + PathPoints(path) + " points, " + PathLength(path) + " units long"
    For i = 0 To PathPoints(path) - 1
        Print PathX(path, i) + ", " + PathZ(path, i)
    Next
    FreePath path
EndIf
```

## Grid paths for 2D and strategy games

For games played on a grid (a 2D dungeon, a strategy map), a **path
grid** finds the cheapest route between cells. Each cell has a cost:
1 is normal, higher is slower to cross (mud, forest), 0 is blocked.

```basic
grid = CreatePathGrid(10, 10)
For y = 0 To 7
    SetPathCost grid, 5, y, 0              ; a wall with a gap at the bottom
Next
SetPathCost grid, 2, 2, 4                  ; a swamp: crossable, but slow
path = FindGridPath(grid, 0, 0, 9, 0)    ; may step diagonally; a last argument of 0 stops that
For i = 0 To PathPoints(path) - 1
    Print PathX(path, i) + ", " + PathY(path, i)   ; column, row
Next
```

`TileMapPathGrid(map)` makes a grid from a [tile map](14-2d-games.md#tile-maps),
with every tile blocked and every empty cell open.

## Behaviour trees

A **behaviour tree** decides what a character does, from simple rules
written as a tree: "if the player is close, chase; otherwise, if hurt,
run away; otherwise patrol".

Write the tree in a text file, one node per line, children indented
under their parent:

```text
selector
  sequence
    if health < 30
    do flee
  sequence
    if distance < 10
    do chase
  do patrol
```

| Node | Means |
|---|---|
| `selector` | try each child in turn until one succeeds |
| `sequence` | do each child in turn while they succeed |
| `invert` | its child's success counts as failure, and the other way round |
| `if condition` | succeeds when the condition is true; compares parameters and numbers |
| `do action` | an action for the program to carry out |

The program gives each character's parameters, asks the tree which
action to do, and does it:

```basic
guardMesh = CreateCube()
player = CreateSphere()
brain = LoadBehavior("guard.txt")
SetBehavior guardMesh, brain
; each frame:
SetBehaviorParam guardMesh, "distance", EntityDistance(guardMesh, player)
SetBehaviorParam guardMesh, "health", 80
Select BehaviorAction(guardMesh)
    Case "chase" : PointEntity guardMesh, player : MoveEntity guardMesh, 0, 0, 0.1
    Case "flee" : PointEntity guardMesh, player : MoveEntity guardMesh, 0, 0, -0.1
    Case "patrol" : TurnEntity guardMesh, 0, 1, 0
End Select
```

The tree is checked every time `BehaviorAction` is called, so a more
important branch takes over as soon as its condition becomes true (the
guard stops patrolling the moment the player comes close). When an
action has finished, `BehaviorResult entity` tells the tree, so a
`sequence` can go on to its next step.

Trees can also be built in code (`CreateBehavior`, `BehaviorSelector`,
`BehaviorSequence`, `BehaviorIf`, `BehaviorDo`) or from a string with
`BehaviorFromText`. One tree can be shared by every guard: each
character keeps its own parameters and progress.

## Try it yourself

The first two exercises print their answers in the console. The third is a
small game.

1. **Maze runner.** Make a maze on a grid 9 across and 5 down. A wall runs down
   column 2 from the top, leaving a gap in the bottom row, and another wall runs
   down column 5 from row 1, leaving a gap in the top row. Find the way from the
   top-left corner to the bottom-right corner (no diagonal moves) and print the
   maze, with `#` for walls, `*` for the route, `S` for the start and `E` for
   the end.
   *Hint: a cost of 0 blocks a cell, and `PathX` and `PathY` give the cells of the route in order.*
2. **Mud.** On a grid 7 across and 3 down, start at the left of the middle row
   and walk to the right of the middle row. Make three cells of mud (cost 5) in
   the middle row, in columns 2, 3 and 4. Print the route cell by cell. Does
   the route go through the mud or round it?
   *Hint: add up the costs: three steps through mud cost 15, and going round costs only two steps more.*
3. **Guard.** On a flat floor, a guard (a cube) walks on a patrol. When you (a
   sphere, moved with the arrow keys) come within 12 units it chases you.
   Pressing Space when you are within 3 units hurts it by 20 health, and when
   its health is below 30 it runs away instead. At 0 health, it is out and you
   win. Show what the guard is doing on the screen.
   *Hint: write the tree as text for `BehaviorFromText`, with the `flee` branch first so it beats `chase`.*

### Answers

1.

```basic
Const W = 9, H = 5
grid = CreatePathGrid(W, H)
Dim map$(W - 1, H - 1)
For y = 0 To H - 1
    For x = 0 To W - 1
        map(x, y) = "."
    Next
Next

; the first wall: column 2, rows 0 to 3
For y = 0 To 3
    SetPathCost grid, 2, y, 0
    map(2, y) = "#"
Next
; the second wall: column 5, rows 1 to 4
For y = 1 To 4
    SetPathCost grid, 5, y, 0
    map(5, y) = "#"
Next

path = FindGridPath(grid, 0, 0, W - 1, H - 1, 0)     ; 0: no diagonal moves
If path = 0
    Print "There is no way through!"
    End
EndIf

For i = 0 To PathPoints(path) - 1
    map(Int(PathX(path, i)), Int(PathY(path, i))) = "*"
Next
map(0, 0) = "S"
map(W - 1, H - 1) = "E"

For y = 0 To H - 1
    row$ = ""
    For x = 0 To W - 1
        row = row + map(x, y)
    Next
    Print row
Next
Print "The route has " + PathPoints(path) + " cells"
```

```output
S*#.*****
.*#.*#..*
.*#.*#..*
.*#.*#..*
.****#..E
The route has 21 cells
```

The path grid and the text map are two copies of the same maze: the grid is
what `FindGridPath` searches, and the text array is only for printing. A cost
of 0 blocks a cell, and the last argument `0` stops the route from
moving diagonally. The route has to go down to the gap in the bottom row,
up through the gap in the top row, and down again to the end.

2.

```basic
grid = CreatePathGrid(7, 3)
For x = 2 To 4
    SetPathCost grid, x, 1, 5        ; mud in the middle row
Next

path = FindGridPath(grid, 0, 1, 6, 1, 0)
route$ = ""
For i = 0 To PathPoints(path) - 1
    route = route + "(" + Int(PathX(path, i)) + "," + Int(PathY(path, i)) + ") "
Next
Print route
Print "Cells: " + PathPoints(path)

For i = 0 To PathPoints(path) - 1
    If PathY(path, i) <> 1 Then Print "The route goes round the mud." : End
Next
Print "The route goes through the mud."
```

```output
(0,1) (1,1) (1,2) (2,2) (3,2) (4,2) (5,2) (5,1) (6,1) 
Cells: 9
The route goes round the mud.
```

Walking straight along the middle row would pass seven cells and cost 15 for
the three mud cells. Going round by the top or bottom row takes nine cells
but each costs only 1, so the total is much less, and the path-finder takes
that. The last lines check whether any cell of the route left the middle row.

3.

```basic
Graphics3D 1280, 720
camera = CreateCamera()
PositionEntity camera, 0, 45, -30
CameraLookAt camera, 0, 0, 0
light = CreateLight(LIGHT_DIRECTIONAL)
TurnEntity light, 60, 20, 0

floor = CreatePlane()
EntityColor floor, 60, 90, 70

player = CreateSphere(16)
PositionEntity player, 0, 1, -15
EntityColor player, 80, 200, 255

guard = CreateCube()
PositionEntity guard, 0, 1, 10
EntityColor guard, 230, 80, 60

; the guard's brain, written as text, one node per line
tree$ = "selector" + Chr(10)
tree = tree + "  sequence" + Chr(10)
tree = tree + "    if health < 30" + Chr(10)
tree = tree + "    do flee" + Chr(10)
tree = tree + "  sequence" + Chr(10)
tree = tree + "    if distance < 12" + Chr(10)
tree = tree + "    do chase" + Chr(10)
tree = tree + "  do patrol"
brain = BehaviorFromText(tree)
SetBehavior guard, brain

health = 100
won = False
action$ = "patrol"

While Not KeyHit(KEY_ESCAPE)
    If KeyDown(KEY_LEFT) Then TranslateEntity player, -0.2, 0, 0
    If KeyDown(KEY_RIGHT) Then TranslateEntity player, 0.2, 0, 0
    If KeyDown(KEY_UP) Then TranslateEntity player, 0, 0, 0.2
    If KeyDown(KEY_DOWN) Then TranslateEntity player, 0, 0, -0.2

    If Not won
        distance# = EntityDistance(guard, player)
        If KeyHit(KEY_SPACE) And distance < 3 Then health = health - 20
        If health <= 0
            won = True
            HideEntity guard
        Else
            SetBehaviorParam guard, "health", health
            SetBehaviorParam guard, "distance", distance
            action = BehaviorAction(guard)
            Select action
                Case "chase"
                    PointEntity guard, player
                    MoveEntity guard, 0, 0, 0.12
                Case "flee"
                    PointEntity guard, player
                    MoveEntity guard, 0, 0, -0.12
                Case "patrol"
                    TurnEntity guard, 0, 1, 0
                    MoveEntity guard, 0, 0, 0.05
            End Select
            PositionEntity guard, Clamp(EntityX(guard), -35, 35), 1, Clamp(EntityZ(guard), -35, 35)
        EndIf
    EndIf

    RenderWorld
    Text 10, 10, "Guard health: " + Int(Max(health, 0)) + "   Guard is: " + action
    Text 10, 30, "Arrows move, Space hits the guard when you are close"
    If won Then Text 640, 340, "You win!", True, True
    Flip
Wend
```

The tree is asked what to do every frame. Its first branch (health below 30,
then flee) is tried first, so a hurt guard runs away even if you are near. If
that fails, the second branch chases when you are within 12 units, and the
last line, `patrol`, is the default. The program supplies the two numbers the
tree compares, `health` and `distance`, and carries out whichever action comes
back with a `Select`. The guard keeps its position inside the floor, and after
a win nothing more updates but the loop still runs, so Escape quits.
